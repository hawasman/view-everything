# S3 Remotes via `rusty-s3`, blocking `ureq` and the OS keyring

S3 Remotes list the bucket with ListObjectsV2 (1000 keys a page). Requests are presigned by `rusty-s3` (no I/O, pure-Rust signing) and sent by blocking `ureq` with rustls; the full async AWS SDK was rejected because it brings a tokio runtime and a large dependency tree for one read-only call, and the app has no async runtime in its scan path. Custom endpoints (R2, MinIO, B2, Wasabi) are the same code with an endpoint and a path-style option. An endpoint named by an IP address or `localhost` is always reached path-style, since the bucket cannot be a subdomain of it.

Credentials follow the standard chain, read by a small `~/.aws` ini parser: keys typed into the dialog, a chosen profile, `AWS_*` variables, then `AWS_PROFILE`/`default`. Typed secrets are stored with the `keyring` crate (Secret Service, Keychain, Credential Manager) under service `view-everything` and the Remote's identity; settings.toml holds only the access key ID. Not supported: role-assuming and SSO profiles, and servers with a private CA (rustls uses the bundled web roots).

## Addendum: FTP Remotes via `suppaftp`

FTP Remotes use `suppaftp` 12 (synchronous, `rustls-ring` feature) for the control and passive data channels; the async and tokio variants stay off, in line with the decision above. It shares the `rustls` already in the tree through `ureq`, and ve-scan names `rustls` and `webpki-roots` directly to build the TLS client (bundled web roots again, so no private CAs). Explicit FTPS (`AUTH TLS`, `PROT P`) is the default and plain FTP is a per-Remote choice made on purpose; the password goes in the OS keyring through the same helper as S3's secrets, filed under the Remote's identity `ftp://user@host:port/path`. Listings are MLSD where `FEAT` offers it, else `LIST` in unix or DOS format, parsed in ve-scan rather than by suppaftp's parser, so that a time without a year reads as the nearest past date and an unreadable line stops the prune. Not supported: implicit FTPS (port 990), active mode, a private CA, and FTP servers that list only with `NLST`.
